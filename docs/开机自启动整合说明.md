# 开机自启动整合说明（方案 A）

更新日期：2026-10-26。用户已反馈整合后可以使用。

## 启动流程

Windows 当前用户登录 → 延迟 15 秒 → `native/start-logon.ps1` → `start-native.ps1 -OpenDisplay` → 打开电脑端 Camo（若未运行）→ 复用 `CamoScanPlatform` 启动 PostgreSQL、Waitress 网页、二维码服务、业务处理和采集 → 网页及数据库健康检查通过 → `native/kiosk.py` 全屏打开岛台。

手机仍须打开 Camo、连接电脑、保持前台且不锁屏。后台不等待手机连接才打开页面；手机未连接时不保证可以扫码。岛台每次打开从空白开始，展示逻辑、页面布局、扫码匹配及提速行为沿用原平台。

这是登录 Windows 后启动，不会自动登录 Windows。程序无需 Docker 或 GPT。

## 使用入口

以下文件均在 `deploy-qr-camera` 中，先完成 [本机运行说明](本机运行说明.md) 中的本机环境配置。

| 入口 | 行为 |
| --- | --- |
| `启用开机自启动.cmd` | 注册或更新当前安装位置的登录任务；后续登录自动运行 |
| `关闭开机自启动.cmd` | 禁用登录任务；不删除数据，也不停止当前服务 |
| `打开Camo扫码岛台.cmd` | 手动启动后台并全屏打开岛台 |
| `开始Camo扫码.cmd` | 保留原行为，只启动后台，不自动打开网页 |
| `停止Camo扫码平台.cmd` | 请求后台安全停止，包含数据库 |

全屏退出按 `Alt+F4`，退出窗口后扫码后台仍运行。关闭后可以再次使用手动全屏入口。全屏窗口由独立浏览器配置目录 `native/kiosk-browser/` 管理，正常运行期间通过锁避免重复打开；该目录不上传 Git。

登录任务名 `CamoScanPlatform-Logon`，Interactive/Limited 权限，不保存 Windows 密码；失败最多重试两次、间隔一分钟，无固定运行时限。岛台无需账号认证，直接访问现有公开展示页，不引入自动保存密码或会话交接。

若需删除登录任务，在此目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install-autostart.ps1 -Remove
```

脚本只处理自己的登录任务。如果同名任务指向其他安装位置则报错，不覆盖。更换安装目录前，应先在原目录停用并移除原任务，再在新目录安装。

## 与 Zxxx 仓库的边界

本次根据 [Zxxx](https://github.com/Lrf-create/Zxxx) 的登录延迟启动和 kiosk 全屏设计，适配现有扫码后台。只更新 `camo-qr-platform`，不修改或推送 Zxxx。

- 不复制 Zxxx 的数据库、runtime、虚拟环境和本机凭据。
- 不引入其单独启动 PostgreSQL/Django 开发服务器的入口，继续使用现有原生后台和同一个数据库。
- 不依赖其 `apps.accounts.local_credentials` 接口，不携带默认账号密码。
- 保留任务命名区别：本项目使用 `CamoScanPlatform` 和 `CamoScanPlatform-Logon`；Zxxx 使用 `MedicalDevicePlatform-Logon`。它们是替代部署入口，不应同时启用去启动同一平台；不同任务名并不意味着共享端口时能并行运行。
- 本机检查仅存在本项目的两项任务，未发现 `MedicalDevicePlatform-Logon`。

## 验证与排查

新增测试验证重复请求不会再启动窗口、窗口退出释放锁、启动失败释放锁、浏览器异常退出向上报错；PowerShell 入口完成语法检查。试运行确认后台启动及 Camo 图像进入识别服务，并检测到岛台浏览器窗口；之后用户反馈可以使用。未将手动试运行描述为已自动验证重启全链路。

启动日志为 `native/logon-startup.log`、`native/kiosk.log` 和原后台日志。任务保持 Running 可表示全屏浏览器监控仍在运行，不代表启动失败。人工关闭窗口后登录任务可正常结束，后台任务继续运行。

源码仓库不包含数据库、密钥、浏览器配置和二进制运行环境，克隆后仍需单独部署。

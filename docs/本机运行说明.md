# 本机运行说明

## 当前已部署电脑

现有部署位于 `D:\医院\CODEX开发`，桌面“Camo扫码平台”调用其中的启动入口。无需打开 GPT 或 Docker。不要移动或删除现有 Python 运行时、PostgreSQL 数据目录和本机私密配置。

已启用登录自启动：登录 Windows 后延迟 15 秒，自动启动扫码后台和电脑端 Camo，服务就绪后全屏打开岛台。原桌面入口仍可启动后台，再手动打开 `http://127.0.0.1:8000/display/sterile-supply/`。首次打开显示空白，随后扫码才显示。本次扫描内容在关闭页面后不再显示，历史数据仍保留在数据库。

二维码内容须对应数据库器械包的 QR 标识；任意文字或未登记二维码不会自动生成器械包。再次识别同一码前，将二维码移出画面后再放回。

## 新电脑部署边界

仓库仅保存源码。新电脑需要先准备以下环境，由部署人员完成初始化；不能只双击源码中的启动入口。

1. 安装官方 Camo Studio 和手机 Camo，确认虚拟摄像头可用。
2. 准备 Windows Python 运行时，路径必须满足 `deploy-qr-camera/python/python.exe` 和 `pythonw.exe`。当前启动脚本使用此布局，普通虚拟环境的 `Scripts/python.exe` 路径不能直接替代。
3. 使用该 Python 安装 `deploy-qr-camera/native/requirements.txt` 中的依赖。
4. 准备 PostgreSQL 16，原部署布局为 `D:\CamoScanPlatformNative\pgsql\bin` 和 `D:\CamoScanPlatformNative\pgdata`，端口 5433。数据库通过单独的安全备份恢复，或新建空库后执行 Django 迁移。不要把真实数据库上传 GitHub。
5. 根据 `native/settings.example.json` 创建本机 `settings.json`，生成独立随机密钥并设置真实数据库账号。`QR_DATABASE_URL` 与 Django 的 `DB_*` 必须指向同一数据库，URL 中的特殊字符须编码。
6. 根据 `native/installation.example.json` 创建 `installation.json`，指向实际 PostgreSQL 根目录。
7. 数据库启动后，用 `python native/runtime.py manage migrate`、`python native/runtime.py manage collectstatic --noinput` 和必要时 `python native/runtime.py manage createsuperuser` 初始化平台。以上命令在 `deploy-qr-camera` 中执行，`python` 指该目录内运行时。
8. 验证表结构、数据库连接和静态文件后，部署人员才创建 `native/migration-complete.json` 标记文件；它只表示本机初始化已核验，不会代替数据库迁移。不得提前创建来绕过错误。
9. 运行 `开始Camo扫码.cmd`。脚本创建或复用当前安装位置的按需计划任务 `CamoScanPlatform`；移动安装目录前应由部署人员处理旧任务指向。
10. 确认手动启动和扫码正常后，运行 `启用开机自启动.cmd`，注册当前用户登录任务。手动全屏入口为 `打开Camo扫码岛台.cmd`。详细行为及取消方式见 [开机自启动整合说明](开机自启动整合说明.md)。

`app/docker_api.py` 是保留的旧文件名，本机入口直接运行它，不依赖 Docker。

## 故障排查

- 拒绝连接：平台未启动或启动失败，先运行桌面入口，再检查 `native/launcher-error.log` 与 `native/supervisor.log`。
- 黑屏/很慢：先检查电脑 Camo 预览是否真实持续变化，手机保持前台且不锁屏；虚拟占位画面不能用于测速。
- 已识别但不显示：确认展示页已经打开、二维码登记在同一数据库、重新将二维码移入画面，并检查 `native/qr.log` 和 `native/worker.log`。
- 图像格式配置保存在 `camera-config.json`：Camo、YUY2、1280×720。修改后须重启采集。
- 查询本机识别服务健康状态：`http://127.0.0.1:8001/database/health`。

日志可能含二维码或业务信息，排查时应单独保管。

# Camo 扫码平台

将 Camo 手机摄像头、二维码识别服务与现有消毒供应平台连接起来。Windows 本机运行；日常启动无需 Docker，也无需打开 GPT。

## 已完成的功能

- 原桌面入口启动 PostgreSQL、网页平台、识别服务和摄像头采集；保留不自动打开网页的行为。
- 可启用 Windows 当前用户登录自启动：登录后延迟 15 秒，启动 Camo 和扫码后台，服务就绪后全屏打开岛台。无需保存平台账号或 Windows 密码。
- 识别到二维码后，通过 PostgreSQL 提交表匹配已有器械包资料，显示器械名称和配置数量。
- 展示页每次打开从空白开始，只显示本次打开后扫描的内容；离开、重开或连接中断后恢复空白。数据库历史保留。
- 连续三帧确认、重复扫码抑制、多码暂停及错误数据处理。
- 摄像头读取与发送分开执行，只处理最新帧；复用本机 HTTP 连接；网页每 300 毫秒查询一次。
- 后台进程退出后重启；摄像头长时间无输出时重新启动采集。

## 日常使用

1. 手机打开 Camo 并连接电脑，手机保持前台且不锁屏。
2. 已启用自启动时，登录 Windows 后等待岛台全屏出现；电脑端 Camo 未运行时会尝试自动打开。
3. 未启用自启动时，可运行 `deploy-qr-camera/打开Camo扫码岛台.cmd`；原桌面“Camo扫码平台”也可继续使用，随后手动打开 <http://127.0.0.1:8000/display/sterile-supply/>。
4. 将数据库中已有的二维码完整放入画面，保持清晰稳定，等待页面显示。
5. 关闭展示页会清空本次展示；需要停止全部后台服务时，运行 `deploy-qr-camera/停止Camo扫码平台.cmd`。

关闭网页不等于停止后台采集。Camo 负责提供画面，二维码识别由本项目完成。页面显示数据库配置数量，并不通过图像清点器械。

全屏窗口使用 `Alt+F4` 关闭。配置、取消及与 Zxxx 仓库的关系见 [开机自启动整合说明](docs/开机自启动整合说明.md)。

# 功能与验证

## 数据路径

Camo 手机画面 → Windows 虚拟摄像头 → 最新帧采集 → 本机 QR 服务 → PostgreSQL 的 A 口提交表 → 平台查询器械包 → 展示页。

扫描展示提交不携带业务明细，不改变器械包出入库状态和库存；原有 A/B 口业务处理仍由平台服务处理。无效二维码作为数据错误处理。

## 提速修改

- 连续读取摄像头，单槽缓冲只保留最新帧，读取与 HTTP 发送分别执行。
- 发送间隔按每次发送开始时间计算，目标上限 10 帧/秒，避免处理时间再叠加固定等待。
- 本机 HTTP 连接复用，减少重复建立连接。
- Camo 使用 YUY2、1280×720，保留连续三帧确认和去重。
- 页面查询周期由原配置缩短至 300 毫秒，避免请求重叠，超时请求主动终止。

现场不同时间窗口采样：旧采集约 2.49 帧/秒，更新后约 3.86～4.45 帧/秒；其中一次源摄像头约 28.81 帧/秒，平均待发送帧年龄约 17.24 毫秒。场景和采样窗口不同，以上不是严格控制变量的性能对比，也不保证每次扫码固定时延。二维码大小、清晰度、手机连接及电脑负载都会影响速度。

## 展示会话

页面打开时记录提交序号，只接受其后的扫描。页面加载不读取历史扫描作为初始内容；离开页面清空展示，浏览器返回时重新建立会话。连接失败时清空并在恢复后重建基线。旧扫描数据库记录保留。

## 验证范围

整理前已验证识别服务与缓冲/连接复用相关测试 16 项、展示页相关测试 12 项；本机无 Docker 的运行链路已用于真实扫码写库。仓库导出后测试结果记录在 `验证结果.md`。

源码导出中的账号导入测试使用临时生成密码，未携带本机账号 CSV。实际相机效果仍需在 Camo 连接、预览持续正常时验证。
